# 谷地外卖店后续计划

当前 2D 经营原型在 `feature/djwcb2333/market-loop` 分支，首个可玩提交为 `77e815a`。已有教学、采集、夜探、付费摆渡、双灶营业和跨天升级。玩法数值、UML、昼夜状态图、系统架构和接口集中在[外卖店设计说明](Design.md)。本轮实际新增、修改和保留的职责，以及新玩法的 CCR 冻结口径，见[外卖原型变化图](ChangeMap.md)。

## 1. 收尾并冻结 2D

| 工作 | 完成条件 |
|---|---|
| 试玩入口和教学 | 用仓库新检出导入 Godot .NET，从默认场景走完运货教学，签收后进入第一天。 |
| 探索和返航 | 白天与夜间各试一次采集。检查受光、雨和夜晚变果。到花庭下车后能从车板边缘重登并返航，两程各扣 1 单位水。水量不足时能看懂补水提示。 |
| 营业和收入 | 分别走直接开店与夜探后开店。确认两口灶可同时计时，预留不会重复占料，收款只补对应窗口。打烊后余额与库存结转，攒钱能买到快灶。 |
| 试玩数值 | 核对 180 秒白天、120 秒直接营业和 90 秒夜探加 60 秒营业的节奏。确认采集范围、往返水量、售价和 36 金币升级价是否适合首轮试玩。调整时同步设计表。 |
| 留存基线 | 保存可运行入口、试玩结果、当前数值表和架构图。通过后以该提交创建外卖 2D 基线标签，建议名 `market-2d-baseline`。 |

当前已有 134 项领域检查，以及旧运货路线和新经营路线的自动复测。基线冻结前再以键盘和鼠标手动完成上述两种夜间路线。

## 2. 把外卖玩法接入 3D

从冻结的外卖 2D 提交切出 3D 开发分支，在仓库已有的 `BorrowingSun3D` 场景上分段接入。

| 顺序 | 要实现的内容 | 该段验收 |
|---|---|---|
| 共享规则 | 把 `MarketRun`、`TakeawayShop`、`ForageSpot` 及其食材、配方、订单类型链接进 3D 工程。塔台继续使用共享 `TowerMechanism` 和摆渡扣水接口。 | 两个工程编译同一份规则。相同条件下，菜单、配方、预留、双灶计时、扣水和升级结果一致。 |
| 采集、昼夜和摆渡 | 用 3D 标记放置采集点，用角色落地和实际距离判断采集及上车。接入 3D 光路、降雨和夜晚状态。把车程与两岸停靠映射到 3D 实体和碰撞。 | 走到场景标记能采集，夜间无阳光。实际走过东岸和花庭，测试下车再登船、回程和无水拒绝发车。 |
| 外卖店与交互 | 把黄昏选择、菜单、两个订单窗口、账目和升级接到 3D HUD。切换至营业时处理角色输入和鼠标焦点。 | 从教学出发，两晚内完成收款、跨天结算并买快灶。直接营业和夜探两条路线都能用。 |
| 两版比较与验收 | 用同一份场景验收清单复测两版，记录版本号、操作、结果和仍待修正的差异。更新 3D 类图和变化图。 | 2D 和 3D 可各自运行。报告能说明哪些规则复用、哪些类因空间和界面改变。若需要计算 CCR，以新外卖 2D 基线冻结的类清单为分母。 |

2D 的像素采集距离需要按 3D 场景尺度和角色体型重新设定。食材数量、配方、时段、摆渡用水和升级价格以冻结的数值表为准。
