## 固定玩法合同

单人、单个连续短关卡，Godot 4.7.1 .NET / C# / net8.0，Compatibility 渲染。2D 完整冻结后，再制作规则相同的 Godot 3D。旧 Unity L5 仅作设计来源。

西岸上塔 → 雨升至高位锁定 → 风接北桥 → 步行到采光庭调采日镜并施晴 → 回塔 → 风接东岸，同时塔镜送光到村庄 → 持续受光解锁一箱水果 → 手动启动原水转配重 → 玩家上车并发车 → 到站下车确认交付 1/1。

采光庭是中间里程碑。只交付一箱，不做分数、倒计时失败、战斗、背包、存档、多关卡、多人、船鱼、鹿岛和长对白。保持简单的可读几何和颜色反馈，正式资产不作为框架任务前置。

## 已决定的行为

| ID | 决策 | 理由与验收 |
|---|---|---|
| D01 | 顺序遵守原计划 01 三岸、02 光路、03 货运、04 冻结 2D、05 做 3D | 不把现在的灰盒标成最终 2D |
| D02 | 2D 单屏侧视；3D 固定斜视，允许镜头跟随但不自由绕场旋转 | 让三岸、桥口、光线同时可读；镜头差异不改变规则 |
| D03 | 风作用塔时显式选择岸口；北、东、入口方向分别显示 | 不依赖隐含的两停点循环。旧 Cast(Wind) 仅为原灰盒兼容 |
| D04 | 镜面三档转动，仍使用有限镜面真实求交 | 不把“角度正确”直接当作接光成功 |
| D05 | 天气按目标保留；离开设备不清空；Q 只收当前目标；R 清全局 | 塔和采日镜状态独立 |
| D06 | 连续受光被打断则未完成计时清零；水果解锁后永久保留到 R | 反馈明确，防止重复奖励 |
| D07 | 转水需手动启动；断光自动暂停，恢复有效条件后继续；再次操作可暂停 | 保留已转水量，不要求重新施令 |
| D08 | 原水总量由 TowerMechanism 同时拥有；进入配重后禁止补雨及排水下降 | 防止复制水、下降导致运输卡关；R 是完整回退 |
| D09 | 发车要求：水果、实时光、东岸接轨、满配重、玩家在车上 | 五项 HUD 指示灯分别反馈拒绝原因 |
| D10 | 发车后不再依赖光；行驶期间禁止主动下车，异常失足回车内安全点 | 车不会因失光停在谷中，玩家不会错失唯一货车 |
| D11 | 到站允许下车，靠近交付点按 E 确认；重复操作不增加计数 | 明确成功结束，非到站即自动通关 |
| D12 | 落水回最近有效岸/塔安全点；乘车阶段回车上；不清空机关进度 | 空间安全点由场景持有，规则状态不被表现层重建 |
| D13 | 开始页说明目标和控制；局部交互提示；结束页显示交付与 R 重开 | 无需额外关卡或叙事系统 |
| D14 | 所有引擎版本和参数变更有记录；初始参数作为两版共享规则 | 两版以同样验收情景比较 |
| D15 | 中英双语职责说明、英文类名；图和源文件保存在仓库 | 不依赖外部设计文件才能交接 |
| D16 | Windows x64 和 macOS arm64 都列为正式验证平台 | 本机不能证明 macOS 通过；必须保存该平台新日志 |

## 完整关卡的输入合同

| 输入 | 功能 | 接入状态 |
|---|---|---|
| A/D、左右箭头 | 2D 行走 | 已有 |
| 1 / 2 / 3 | 选择雨 / 风 / 晴 | 1、2 已有；3 待场景接入 |
| E | 对当前设备施令；车辆上下车/交付采用明确情境提示 | 施令已有；新增目标待接入 |
| Q | 收回当前目标天气 | 当前只接塔；镜面局部收令已在规则层实现 |
| Z / X | 选择前一个/后一个塔目标岸口 | 待场景接入；先选择后按 E 施风 |
| F | 在塔设备排水 | 已有；有配重时规则拒绝 |
| T | 启动/暂停转水 | 规则入口已有，输入待接入 |
| R | 全局重开 | 灰盒已有；完整场景须同时调用 GameSession.Reset |

目标选择优先级：行驶中的货车约束 > 到站交付点 > 最近可交互设备；等距离按稳定节点 ID 排序，UI 只高亮一个。3D 采用 WASD 平面移动，相同的天气与交互键。初始不加入跳跃。
